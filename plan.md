# Plan — Asser Nafti portfolio skills expansion

## Implementation approach

Keep the portfolio as a single accessible static page served on port 3000. Preserve the existing visual language, project order, live-demo links, source links, project-cover treatment and LinkedIn-only contact path. Expand the structured metadata, project case studies and Toolkit so that the content reflects the complete evidence found in the Nafti AI, Clash AI and Fashion In Motion repositories.

The skills presentation is organized by evidence rather than as one keyword list:

- frontend foundations and browser state;
- product UX and commerce flows;
- Python web engineering;
- AI, ML and image systems;
- voice and language experiences;
- accounts, state and sharing;
- mobile and native delivery;
- cloud, serverless and deployment;
- reliability, security and operations;
- testing and developer tooling.

Every group names the projects that support it. Provider-dependent functions, manual D17 reconciliation and the VoxCPM voice pilot are explicitly qualified. No client, employment, revenue, user, performance or mastery claim is added.

## Project structure

- `index.html` — complete one-page portfolio, metadata, JSON-LD, project case studies and evidence-linked Toolkit.
- `styles.css` — existing editorial responsive system, dark project panels, accessible focus states and mobile breakpoints.
- `script.js` — footer year update.
- `assets/` — existing local visual assets and favicon.
- `manus-routes.json` — static home route declaration.
- `app.config.ts` — durable WebDev project logo metadata.
- `TODO.md` — outcome criteria and factual-integrity boundary.

## Design direction

**Design movement:** editorial product portfolio with Swiss-influenced structure and warm technical accents.

**Core principles:** evidence before adjectives; strong typographic hierarchy; dark project panels for product contrast; readable density on small screens.

**Color philosophy:** paper tones keep the long skills inventory calm and readable; orange marks implementation energy and links; navy and charcoal give the product cards a technical, credible frame.

**Layout paradigm:** asymmetric editorial columns and alternating project rows, followed by a long evidence ledger rather than a centered keyword wall.

**Signature elements:** circular A/ wordmark, orbit-and-line project diagrams, orange annotation chips.

**Interaction philosophy:** links and buttons expose the next concrete action; project metadata labels work as personal projects; evidence notes clarify scope instead of overselling it.

**Animation:** retain subtle hover transitions and smooth anchor scrolling; respect `prefers-reduced-motion` already defined in the stylesheet.

**Typography system:** system sans-serif for interface and evidence; Playfair Display only for the Fashion In Motion wordmark.

**Brand essence:** a product-minded web and Android developer who connects interfaces, APIs and practical AI features; precise, curious, grounded.

**Brand voice:** direct, implementation-led and transparent about limits. Example lines: “Useful products. Clear interfaces. Built to ship.” and “Provider availability and quotas can affect AI features.”

**Wordmark and logo:** compact A/ mark paired with a spaced uppercase name.

**Signature brand color:** warm orange, used for focus, links and implementation cues.
